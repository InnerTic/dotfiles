# 💥 What is actually killing your disk

When you do:

HF typically does this:

## 1. Downloads full repo snapshot

- model weights (often sharded)
    
- tokenizer files
    
- config files
    

→ stored in:

```
~/.cache/huggingface/hub/
```

---

## 2. vLLM / transformers may create a second layout

Depending on backend:

- mmap mapping OR
    
- temporary compiled weights OR
    
- CUDA-sharded buffers
    

This can spike disk + RAM usage briefly.

---

## 3. Worst case: duplicate staging

Some models (especially MoE / multi-shard):

- get partially re-written into optimized layout
    
- OR re-downloaded if cache mismatch happens
    

So you see:

> “I needed 15GB but 50GB vanished”

That’s usually:

- cache + staging + shards + partial rebuild artifacts

> one clean file

you get:

# 🟡 Why your “50GB download for 15GB model” happens

Common causes:

## 1. Multiple model variants pulled accidentally

- base + instruct + tokenizer variants
    
- vision + text + chat versions
    

## 2. Hugging Face snapshot duplication

HF keeps:

- `blobs/`
    
- `snapshots/`
    

Both coexist → looks like duplication

## 3. Model revision confusion

If no pinned revision:

- HF may re-download slightly different weights
    

## 4. vLLM preloading behavior

vLLM may stage:

- KV cache planning buffers
    
- tensor-parallel splits
